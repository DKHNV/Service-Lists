# Service Lists — архитектура

## Назначение

Service Lists — публичная read-only витрина списков DKHNV.

Она не выполняет DNS-резолвинг, не изменяет исходные репозитории, не имеет backend и не требует VPS.

## Поток данных

```text
DKHNV/<Service>
  ├─ CIDR
  ├─ RouterOS
  └─ DNS
        │
        │ HTTPS / GitHub Raw
        ▼
GitHub Pages: Service Lists
        │
        ├─ просмотр
        ├─ статистика
        └─ скачивание
```

## Источник истины

Источник истины всегда находится в исходном репозитории сервиса.

Service Lists не хранит копии CIDR/RouterOS/DNS и поэтому не может рассинхронизироваться с Raw-файлами.

## Manifest

`site/services.json` содержит только описание источников и точные имена файлов.

Это необходимо, потому что существующие репозитории имеют разные схемы именования, например:

- `YouTube_CIDR.txt`
- `Telegram-CIDR.txt`
- `Discord_CIDR`

## Дата обновления

Основной источник даты — `pushed_at` публичного GitHub REST API для репозитория сервиса.

Metadata кэшируется в `localStorage` на 15 минут, чтобы не расходовать неавторизованный GitHub API limit при каждом обновлении страницы.

Fallback — дата из строки вида `#Gen4 19.04.2026` в CIDR/RouterOS, если она присутствует.

## Безопасность

Удалённые файлы никогда не вставляются через `innerHTML`. Содержимое выводится только через `textContent` в `<pre>`.

GitHub token, cookies приложения, серверные секреты и авторизация отсутствуют.

## GitHub Pages

Workflow только публикует папку `site/` при изменении самого проекта.

Отдельный schedule не нужен: данные загружаются из Raw при открытии страницы.
